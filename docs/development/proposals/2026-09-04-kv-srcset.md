> **不在 review 結束前部署**。本檔不改任何產出鏈。

## 現況（線上實測，Lighthouse mobile · 部署 gh-pages `12706cc`）

`uses-responsive-images` 50 分，線上只剩一個檔：`assets/kv/puritylens.webp`（首屏第一張卡）
浪費 58,821 B（84%）。16 張 KV 母版合計 **1,125,590 B**，每張 1600×1200。

母版受 `scripts/audit-kv.mjs` 的 `SPEC` 約束：`1600×1200`、4:3 ±0.5%、≤200 KB、`.webp`，
掃的是 `site/assets/kv/` 整個目錄 —— **任何非 1600×1200 的檔放進去都會讓 gate 紅**。
母版來源是 `site-assets/kv-ai/<slug>.png`（16 檔，已拍板）與 `site-assets/kv-gen/`。

## 最小改動（三處，全部可逆）

1. **`scripts/build-kv-assets.mjs`**：KV 迴圈多產一份 `site/assets/kv-800/<slug>.webp`（800×600，同一條 sips→cwebp 路徑，
   同一個品質迴圈）。**放在獨立目錄**，`audit-kv.mjs` 的 SPEC 掃描不會碰到它 —— 母版與其 gate 一個字不動。
2. **`scripts/gen-work-v3.mjs:216`**（`stage__bg` 那行）加：
   ```
   srcset="assets/kv-800/<slug>.webp 800w, assets/kv/<slug>.webp 1600w"
   sizes="(min-width: 1440px) 419px, (min-width: 1080px) 482px, (min-width: 768px) 341px, 350px"
   ```
   `sizes` 直接用上表量到的值（斷點對應 `sections.css` 的 grid 欄數），不用 `vw` 近似。
   `src` 仍指 1600 母版 —— 不支援 srcset 的環境行為不變。
3. **`scripts/audit-critical-path.mjs`** 加一段：每張 `stage__bg` 的 `srcset` 兩個候選檔都存在、
   800 變體讀 WebP 檔頭確為 800×600、`sizes` 與 CSS 斷點一致（反向測試：刪一個變體檔 → exit 2）。

**不做的**：不改 modal 的 `.work-modal__shot`（它 clone 同一份 `.stage`，會自動拿到 srcset）；
不引入 `<picture>`；不動 `work-copy.json`；不動 `audit-kv.mjs`。

## 預期效果與驗證

- 首屏 puritylens（mobile DPR 2）：70,316 → 42,062 B；`uses-responsive-images` 預期 50 → 100（線上 Lighthouse 複驗，兩種節流都跑）。
- DPR 3 手機與 ≥1080 桌機仍載 1600 —— 用 `document.querySelector('.stage__bg').currentSrc` 在各視口實測，
  對照上表「需要的像素寬」，選錯即失敗。
- 視覺：800 變體在 DPR 2 的 350 px stage 上是 2.29x，不低於現行 icon 的 2.78x 標準；仍以 3x DPR 並排比對驗證。

## 回退

刪 `gen-work-v3.mjs` 那兩個屬性 → 重建；`site/assets/kv-800/` 整目錄刪除。母版與 gate 從未被動過。
